# OneUI Mods CPU・メモリ監査

今回の作業対象は、同じワークスペースにある19本のAndroidアプリです。初回・更新時の解析、常駐監視、描画、画像・音声バッファ、キャッシュ、ワーカーの寿命を確認しました。機能や品質を下げるための更新間隔変更は行っていません。

| アプリ | 対処・確認した処理 |
| --- | --- |
| DarkAppTools | 初回解析とVector接続情報取得の待機スレッドを、仕事がないときに解放します。配色のルール、画像の解像度、描画への適用タイミングは変更しません。 |
| GalaxyCameraTools | 初回解析とVector接続情報取得の待機スレッドを解放します。撮影FPS、レンズ切り替えのイージング、プレビューバッファ、カメラ要求値は変更しません。 |
| GalaxyCaptureTools | 初回解析とVector接続情報取得の待機スレッドを解放します。録画フレーム、音声の取得範囲・音量・ミックス、回転補正は変更しません。 |
| GalaxyChargeMonitor | 正常終了した読み取りのタイムアウト予約を直ちにキューから取り除き、キャンセル済みの予約オブジェクトを保持し続けないようにします。読み取り項目・間隔・15秒のタイムアウト・読み取り専用という制約は変更しません。 |
| HomePodBridge | 初回解析と操作要求用の直列ワーカーは、30秒仕事がない場合にスレッドを解放します。再開時は即座に実行を受け付けます。PCMバッファ、パケットサイズ、音声の遅延・音量・品質は変更しません。 |
| OneUIHomeTweaks | 診断ログは記録が発生したときだけ2秒後の書き込みを予約します。待機中の定期起床をなくし、記録が続く場合のバッチ間隔と256件の上限は維持します。初回解析・接続情報取得のワーカーも待機時に解放し、同じ配置情報の二重読み取りをなくします。フォルダ・壁紙・クイックパネルの動作と描画頻度は変更しません。 |
| OneUIModsManager | 同時に届く更新結果は、最新の状態を1回のUI通知で反映します。描画中にさらに更新された場合は次の通知を残します。更新確認用のワーカーも待機時に解放します。4件の並列通信、更新確認の間隔、進捗・完了・エラー情報は維持します。 |
| SleepStore | Vector接続情報取得用のスレッドを待機時に解放します。ストアの機能制御や診断の条件は変更しません。 |
| galaxy-adaptive-statusbar | 背景サンプルは採取する画素数だけの配列を1回確保します。従来の採取座標・透明度判定は維持します。低コントラスト判定は輝度を1回並べ替えて、白黒それぞれの従来と同じ十分位値を求めます。自動モードで同じ色の可読性を二重計算せず、入力を変更しない方式では不要な配列コピーを省きます。初回解析・接続情報取得のスレッドも待機時に解放します。更新間隔、キャプチャ頻度制御、フェード・移動・描画品質は変更しません。 |
| galaxy-diag | コマンド用のスレッドを待機時に解放します。診断の内容、権限、応答期限、モデム設定は変更しません。 |
| galaxy-reload | 再読み込みコマンド用のスレッドを待機時に解放します。解除状態の確認・認証・再読み込み対象は変更しません。 |
| galaxy-service-panel | 同じ診断テキストと文字サイズが再通知された場合は、再解析と表示用データの再生成を省きます。元のリストが書き換わるケースを考慮し、前回の値は独立して保持します。初回解析とVector接続情報取得のスレッドも待機時に解放します。モデムの監視・操作・更新頻度は変更しません。 |
| galaxy-shutter-mute | 設定画面が見えない間の確認ループを停止し、再表示時に直ちに確認します。表示中の60秒間隔と設定値は維持します。ViewModelはApplicationのContextを保持し、画面を作り直した後の古いActivityを保持しないようにします。 |
| galaxy-shutter-mute-manager | ViewModelと関連データ取得はApplicationのContextを保持し、画面を作り直した後の古いActivityを保持しないようにします。更新確認・インストール・権限付与・画面表示中の確認間隔は変更しません。 |
| galaxy-update-guard | 操作用のスレッドを待機時に解放します。ブロック対象、保存済み復元情報、起動時の動作は変更しません。 |
| legacy-game-tools | Vector接続情報取得のスレッドを待機時に解放します。ゲームの判定や描画・音声・ロード・スキップの処理は変更しません。 |
| sim-pilot | 通信量取得用のワーカーを待機時に解放します。SIM切り替え・無線監視・速度測定の間隔、通信量の15分キャッシュは変更しません。 |
| tail-adb | 状態変化によって取り消した次回確認の予約を、直ちにキューから取り除きます。頻繁な通知でも古い予約を保持しません。接続監視と復旧の間隔、Tailscale専用の接続制御、転送性能は変更しません。 |
| SimejiClean | APK世代ごとの探索キャッシュと初回読み込み、画面専用ワーカーのonDestroyでの終了を確認しました。継続的なポーリングはなく、初回探索の大きなデータは呼び出し内で解放可能になります。今回の実行コード変更はありません。復元済みソースと未追跡の復元メモを保持します。 |

## 既存の上限と終了処理

- 配色画像は32件、色リストは各128件で上限管理され、描画対象は弱参照を利用しています。
- Capture Toolsの対象一覧は要求元UIDごとに有効期限を管理しています。
- カメラの切り替え画像は演出の終了時に切り離します。描画中の画像を早期にrecycleする変更は避けています。
- HomePod BridgeのPCMはセッション単位の固定バッファを再利用し、音声のパケット間隔・レイテンシを維持しています。
- TailADBのネイティブ監視はネットワークイベントとバックオフを利用する既存構成を維持しています。
- 充電監視は画面停止時に読み取りプロセスとワーカーを終了します。更新ガードは定期的なroot監視を追加しません。

## 制限

これは対象ソースの監査とホスト上の回帰確認です。実機で全アプリを操作した結果や、端末全体での削減率ではありません。特に、先に発生したSurfaceFlingerの状態蓄積の作成元や再発防止を証明したものではありません。画面操作・音声再生・ソフトリブート・SystemUI再起動は実施しません。

## ホスト検証

変更した18本と、実行コードを変更しなかったSimejiCleanのreleaseビルド・lintを確認しました。合計863件のユニットテストが成功しています（シャッター音アプリ2本には既存のユニットテストがありません）。初回キャッシュのSHA-256識別子は汎用フォーマッタの繰り返しをなくし、既存形式との一致を7本で確認しました。
