# Kotlin移行後の動作互換性 — 2026-11-01

全16アプリを対象に、null以外の数値・比較・文字列・コレクション・例外・同期・JVM/JNI契約を再調査した。既存Kotlinの3本は移行による差分がないことも区別して確認した。

## 確定した差と修正

10アプリ・74箇所（strip相当18、空白判定21、分割35）で、文字列処理の仕様を復元した。Service Modeの本物の表示モデルを旧Java/現Kotlinで比較し、NBSP・figure space・narrow NBSPの行が消える、または文字が削られる33ケースの差を再現した。

実装はKotlinのまま。TextCompatibility.ktはKotlin Char/Regexを使用する。JDKのString実装や旧Javaソースへの委譲は行わない。Javaの参照API・元のコンパイル済み試験は比較の基準だけとして使用する。C++・Go・端末の認証や設定は変更しない。

空白はKotlinの標準判定から3種類の改行禁止スペースを除いて旧仕様に揃える。分割は空入力の1要素、先頭のゼロ幅一致抑制、末尾の空要素除去をKotlin Regexの結果から再現する。空入力でも不正な正規表現を拒否する。

## 検証

- 16本のrelease組み立て・Lint成功。現在のJVM656件、失敗・エラー0。
- 変更していない元JavaのJUnit483件を、現Kotlin製品コードへそのまま適用して成功。
- 選んだ非I/Oモデル115メソッド・20,700入力の実行結果/入力変化/例外型を隔離クラスローダーで比較。修正前はService Modeの33ケースで差、修正後は0。
- 79モデル・2,370ケースのコンストラクタ、equals、hashCode、toStringを比較して差0。配列を同じインスタンスで両側へ渡すことで、参照型のhash差を隠さない。
- synchronized/volatile/transient指定を生成済みJVMコードで比較。指定の欠落はない。PrivacyDotsの3つのvolatile追加は以前の別スレッド対策であり、取り除かない。
- 29ネイティブメソッド/5クラスのdescriptor・staticを維持。privateキャッシュのアクセサ等の既知の差は完全バイナリ一致とは区別する。
- Android16/17の専用AOSPエミュレータで10本のrelease APKの実クラスをロード。各APKで65,536文字の空白境界、48分割ケース、不正な正規表現を確認。Service Modeモデルの行/文字保持も成功。プローブのKotlin runtimeを製品へ流用しないよう、APKのクラスローダーはboot親から構築する。

## 範囲と制限

静的調査と、選んだ入力・モデル・契約の差分試験であり、全入力/全端末/全ホストフックの同一動作を証明しない。全カメラ/録画/音声モードの実動作、実際の音声再生、Android16 Samsung実機は未再試験。既存Kotlin3本、テストのないアプリ、対照試験を構築できなかったモデルを合格件数へ上乗せしない。

生ログ、設定、APK/DEXはprivateへ隔離する。配布は署名済みreleaseと対応するソースだけ。公開検証ツールの新しい実装もKotlinとする。移行前Javaは参照スナップショットのまま保管し、製品Androidソースへ戻さない。
